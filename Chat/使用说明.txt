================================================================================
  Chat —— 使用说明
================================================================================

【一、文件夹里有什么】

  Chat.exe            主程序，双击运行（已编译好，不需要 Python，不需要装任何东西）
  apikey.txt          API Key 存放处（必须是这个文件名，放在 exe 旁边）
  提示词.txt          角色设定 / 背景说明 / 回答规则（想让它“懂你”，改这个文件）
  config.txt          可选配置：模型、超时、思考模式、代理（一句话级别的系统提示词）
  Chat.cs             源代码（想改功能就改它，然后双击 build.bat 重新编译）
  build.bat           一键重新编译（用 Windows 自带的 C# 编译器，不用装 VS）
  使用说明.txt        本文件
  selftest.log        自检结果（运行 Chat.exe --selftest 后生成）


【二、第一次使用】

  1) 用记事本打开 apikey.txt，在 “apikey =” 后面填上你自己的 Key，保存。
     写法随便哪种都行：
         sk-abcdefg123456
         apikey = sk-abcdefg123456
         api_key: sk-abcdefg123456
     （# 开头的行是注释，程序会跳过）
     没填 Key 时，程序会在你点发送的时候弹窗提醒，不会带着空 Key 去请求。

  2) 双击 Chat.exe，窗口出现后，在下面那一行里打字，按 Enter 发送。
     （如果不填 Key 就发送，程序会弹窗告诉你缺什么，不会静默失败。）


【三、界面长什么样：极简两行】

  默认是一条约两行高的细长窗口，从上到下就两样东西：

    ┌──────────────────────────────────────────────┐
    │ 光照折射定律 n₁sinθ₁ = n₂sinθ₂                │ ← 一行输出（模型的回答）
    ├────────────────────────────────────┬─────────┤
    │ 帮我解释一下这个公式的意思          │ 移除图片 │ ← 一行输入
    └────────────────────────────────────┴─────────┘

  · 上面那行显示回答（流式逐字出现，会自动滚到最新内容）。
  · 下面那行输入问题：Enter 发送，Ctrl+V 贴图。
  · 贴了图：输入行右边多出一个“移除图片”按钮，点了就撤掉这张图；
    没有图的时候这个按钮不会出现（不占地方、也没有多余的缩略图框）。
  · 输入行右边的“截图”按钮：点一下就能框选屏幕区域截图（用法见下一节）。
  · 一行放不下整个回答，所以：右键 → “查看完整对话”，全文在那里，可以一键复制。
  · 窗口上下不能拉（高度是算出来的），左右可以随便拉宽。

  【所有功能都在右键菜单里】
    发送 / 停止生成 / 清空对话 / 查看完整对话 / 深度思考开关 /
    移除待发送的图片 / 重新读取 Key/配置 / 编辑提示词 / 打开 config.txt，
    另外还有剪切、复制、粘贴、全选输入框。

  想换回大窗口的完整界面：把 config.txt 里的 ui = compact 改成 ui = full，
  重新打开程序即可（两个界面共用同一份配置和 Key，随时切）。


【附：不占任务栏怎么用（托盘图标）】

  【让它变半透明】
    config.txt 里 `window_opacity` 控制窗口透明度（百分比）：
      100 = 完全不透明（默认）    85 = 微微透，隐约看见后面的内容
       70 = 明显透视，适合浮在资料上边看边问      20 = 下限
    改完重新打开程序生效。注意半透明时文字会比不透明时略微发虚一点
    （系统对半透明窗口会关掉字体平滑），这是这个效果的固有代价。

  先记住一条：**点窗口右上角的叉号只是"隐藏到后台"，程序并没有退出。**
  第一次点的时候会弹一条系统通知告诉你这件事。

    想把它叫回来：按 Ctrl+Alt+C，或双击托盘图标，或再双击一次 Chat.exe
    想真正退出：  右键窗口（或托盘图标）→ "退出 Chat"

  默认已经设成不在任务栏显示图标（config.txt 里 show_in_taskbar = off），
  所以任务栏和 Alt+Tab 里都不会出现 Chat，它就在桌面上安静地待着。

  替代入口是右下角**托盘区那个蓝色对话气泡图标**：

    · 双击它        = 显示 / 隐藏窗口（窗口藏起来时，双击就回来）
    · 右键它        = 菜单：显示/隐藏窗口、截图框选、查看完整对话、退出 Chat

  为什么必须有托盘图标：任务栏图标关掉后，窗口一旦最小化或被别的窗口盖住，
  就没有按钮能点回来了。所以程序在关掉任务栏图标时会自动创建托盘图标兜底，
  这是唯一不会让你“把窗口弄丢”的做法。

  全局截图热键（默认 Ctrl+Alt+Q）在窗口隐藏时照样能用 —— 按一下就能截图，
  截完的图会自动挂进对话里，不需要先把窗口调出来。

  窗口藏起来之后想找回来，有三个办法（哪个顺手用哪个）：
    1) 按 Ctrl+Alt+C（显示/隐藏窗口的全局热键，推荐，不用找图标）；
    2) 点任务栏右下角的 ^（“显示隐藏的图标”），找到蓝色对话气泡图标双击；
    3) 直接再双击一次 Chat.exe —— 它不会开第二个窗口，只是把已有窗口叫回来。

  说明：Windows 11 默认会把新出现的托盘图标收进 ^ 折叠区（我实测截图确认过），
  这是系统行为。想让它常驻可见，就把折叠区里的 Chat 图标拖到任务栏上。

  想改回在任务栏显示：把 config.txt 里 show_in_taskbar 改成 on，重新打开程序。


【四、怎么发图片】

  · 截图（Win+Shift+S 或 QQ/微信截图）之后，鼠标点一下输入框，直接 Ctrl+V，
    上方会弹出一条缩略图，写着图片尺寸和大小 —— 这就代表图挂上了。
  · 也可以把图片文件（png/jpg/bmp/gif）直接拖到窗口里。
  · 挂上图之后可以继续打字提要求，例如“这张图里的报错是什么意思”，然后 Enter。
  · 不想发这张图了，点“移除图片 (×)”。
  · 打完字按 Enter 就发送；想换行按 Shift+Enter。
  · 用拼音输入法时，正在拼字状态下按 Enter 是“选字/上屏”，不会误发消息。
  · 大图会自动缩到长边 1600 像素再上传（截图用 PNG 保清晰，照片转 JPEG 省流量），
    所以你粘一张手机拍的几 MB 大照片也不会卡。
  · 图片只在内存里压缩后发走，不会在硬盘上留副本。

  【截图按钮 / 快捷键 Ctrl+Alt+Q】
    · 点界面上的“截图”，或**在任何一个程序里**按 Ctrl+Alt+Q（全局热键，
      不需要先切回 Chat），屏幕会变暗成可框选状态；
    · 按住鼠标左键拖出一个矩形：框线是淡灰色，框内会实时显示“宽 × 高”，
      框外保持原样不受遮挡，方便你对着题目对准边界；
    · 松开左键 → 截图自动挂到对话里（和 Ctrl+V 贴图一样的效果），
      接着打字提问、按 Enter 就发出去了；
    · 想取消：按 Esc 或点鼠标右键。
    · 截图前 Chat 窗口会自动隐身，所以不会把自己截进去；
      快捷键可以在 config.txt 里改（screenshot_hotkey）。

  注意：图片必须用 deepseek-flash 模型（config.txt 默认就是它）。
        如果把 model 改成 deepseek-v4-pro，那个模型不支持图片；
        这时你贴图发送，程序会先弹窗问你要不要本轮临时切回 deepseek-flash，
        不会让你去猜服务端那句英文报错。


【五、深度思考开关】

  界面右下角有个勾选框“深度思考”：
    · 不勾（默认）= 模型直接回答，快，日常问答够用；
    · 勾上         = 模型先输出一段思考过程（灰色小字，会显示在回答上方），
                     再给正式回答。慢一些，但算数、推理、写代码更准。
  config.txt 里 thinking = on 可以让它默认就是勾上的。


【六、怎么让它“懂你”：提示词.txt】

  这个文件里的**整份内容**会被当作系统提示词发给模型，相当于给它设定身份、
  交代你的背景、规定回答风格。默认已经写了一份模板（先给结论、公式要带单位、
  信息不足先问你等），你可以直接改成自己的：

    · 点界面上的“编辑提示词”按钮 → 自动用记事本打开这个文件；
    · 改完保存，**下一条消息就生效**，不用重启程序（每次发送前都会重读一次）；
    · 清空这个文件（或把它删掉），程序就退回使用 config.txt 里的 system_prompt；
    · 优先级：提示词.txt  >  config.txt 的 system_prompt  >  程序内置默认。

  程序启动时的欢迎文字里会写明“当前生效来源”，界面上也能看到是哪一个，
  所以不会出现“我明明改了提示词却没生效”这种糊涂账。

  编码问题已经处理：不管你是用老版记事本（默认存成 ANSI/GBK）还是新版
  （存成 UTF-8），程序都能正确读出中文；自检里专门有一条 GBK 读写的验证。


【七、常见问题】

  Q：它好像"忘记了我的提示词"（提示词.txt 里的设定）？
  A：系统提示词是**每一轮都会单独发一次**的，不会被忘记、也不会被历史裁剪挤掉。
     想自己核实，就在命令行里跑一次：
         Chat.exe --dumprequest
     同目录会生成 请求体导出.txt，里面写清了：提示词来源、提示词全文、
     以及"聊到第 6 轮时 messages 的真实顺序"（第一条永远是 system＝你的提示词）。

     真正会"忘"的是**对话历史**，它只由 config.txt 里的 max_history_messages 决定：
         max_history_messages = 3   → 只记得上一轮，问新题时看不到更早的内容
         max_history_messages = 20  → 记得最近 10 轮左右（推荐）
         max_history_messages = 0   → 不限制（聊很久会越来越贵）
     放大的代价其实很小：上限 40 时每轮多送的历史也就几百到两千字，
     deepseek-flash 非高峰输入价 $0.15/百万 token，约合每轮 0.2 分钱，
     而且重复的前缀会命中缓存，实际更便宜。

  Q：模型偶尔不按提示词的风格回答（比如又开始长篇解析）怎么办？
  A：把 config.txt 里的 reinforce_prompt 改成 on。程序会在你这轮的提问后面
     再贴一次提示词设定——位置紧挨着问题，模型的注意力最强，比只在开头写一次更管用。
     代价是每轮多约 150 token（几乎可以忽略）。改完重新打开程序生效。

  Q：双击没反应 / 一闪而过？
  A：程序不会一闪而过，除非被杀软拦了。先看同目录有没有 selftest.log，
     再右键“以管理员身份运行”试一次。也可以把这台机器的情况告诉我。

  Q：提示“未读取到 API Key”？
  A：三个可能：① apikey.txt 的文件名被系统改成了 apikey.txt.txt（在文件夹里
     勾选“文件扩展名”看一下）；② 文件没和 exe 放同一个目录；③ Key 写成了
     sk-请把这里替换成你自己的Key 没改。改完点界面上的“重新读取 Key/配置”。

  Q：提示 HTTP 401？
  A：Key 不对或已被删除，去 platform.deepseek.com 重新生成一个。

  Q：提示网络请求失败？
  A：这台电脑上不了 api.deepseek.com。如果平时靠代理软件上网，就在 config.txt
     里写 proxy = http://127.0.0.1:7897 （端口按你自己的代理填），然后重新打开程序。

  Q：回答是空的 / 只有灰色思考文字？
  A：勾了深度思考时，模型可能把内容都放在思考里，把勾去掉再问一次即可。

  Q：这台电脑是 Win7 或者 32 位系统怎么办？
  A：Win7 需要装 .NET Framework 4.0 或更高（微软官网免费下载，装一次即可）。
     32 位系统：用记事本打开 build.bat，把最后一行注释里的 /platform:x86 加到
     csc 那行上，双击 build.bat 重新编译出一个 32 位版本即可。

  Q：点了叉号，程序好像还在运行？
  A：这是故意的（和微信、QQ 一样）：叉号只把窗口藏起来，程序继续在后台待命，
     方便你随手按 Ctrl+Alt+Q 截图提问。想真正退出：右键窗口（或托盘图标）→ "退出 Chat"。
     如果你更想要"点叉号就退出"的老行为，把 config.txt 里 close_button 改成 exit。


【八、它到底做了什么（技术说明，给想改代码的你）】

  1) 启动时读 exe 同目录的 apikey.txt 和 config.txt；
     每轮发送前还会重读一次 提示词.txt，所以改完提示词立刻生效；
  2) 调 https://api.deepseek.com/chat/completions，Authorization: Bearer <Key>，
     请求体是 OpenAI 兼容格式，stream = true 走 SSE 流式返回；
  3) 图片走 content 数组里的 image_url 内容块，值是 data:image/png;base64,....；
  4) 多轮对话由程序自己拼接历史（接口是无状态的），只保留最近 N 条，
     并且只保留最近 1 条带图消息的原图，更早的图会被替换成“（原图已省略）”，
     免得聊久了每次上传都是几十 MB；
  5) 全部代码只用 .NET Framework 4.0 的 API（没有 async/await、没有 System.Text.Json），
     所以老 Win10 自带的老 .NET 也能跑；TLS 1.2 是手动放行的，
     这是老 .NET 连现代 HTTPS 服务器最常见的坑。

  自检命令（不弹窗，跑完看 selftest.log）：
      Chat.exe --selftest
  它会验证 Key 解析、JSON 转义、配置解析、图片编码、SSE 解析，
  文本编码识别（UTF-8 / UTF-16 / GBK）、提示词优先级，
  以及真实连一次接口（用假 Key 应该收到 401，收到 401 就说明网络和 TLS 通道是通的）。

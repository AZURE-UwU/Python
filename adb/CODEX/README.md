# ADB 无线调试助手

扫描局域网里开着「无线调试」的安卓手机，一键配对、连接、断开。WinUI 3 界面，绿色文件夹分发，自带 adb。

## 直接使用

双击 `dist\ADBDevTool\ADBDevTool.exe`。整个 `dist\ADBDevTool` 文件夹可以拷到任何 Win10（1809 及以上）/ Win11 机器上运行，不需要预装 .NET 运行时或 Windows App Runtime。

### 手机端（首次）

1. 设置 → 关于手机 → 连点「版本号」打开开发者选项。
2. 设置 → 系统 → 开发者选项 → 打开「无线调试」。
3. 点「使用配对码配对设备」，屏幕上会出现一个 **IP:端口** 和 **6 位配对码**，保持这个窗口不要关。
4. 手机和电脑必须连同一个 Wi-Fi（同一网段）。

### 电脑端

1. 打开程序，点「**扫描局域网**」。列表里会出现局域网内开着无线调试的设备。
2. 点「**无线调试配对**」，把手机上第 3 步显示的 IP:端口和 6 位配对码填进去，点「开始配对」。
3. 配对成功后程序会自动连接，设备状态变成绿色「已连接」。
4. 之后再用就简单了：开手机无线调试 → 点「扫描局域网」→ 选中设备 → 点「**连接**」。

### 投屏

「投屏」按钮需要选中一台状态为「已连接」的设备，点一下弹出一个独立的 scrcpy 窗口，位置尺寸由 scrcpy 自己管；按钮随即变成「关闭投屏」，再点一次结束会话（结束不需要再选设备）。

投屏相关的两个开关都在顶部工具条的「**设置**」里，改完对下一次投屏生效，设置本身会被记住：

- **投屏时关闭手机屏幕**：给 scrcpy 加 `-S`，手机屏幕熄灭但镜像和鼠标键盘控制照常，scrcpy 退出时自行恢复屏幕状态。
- **显示 scrcpy 命令行窗口**：scrcpy 自己会带出一个命令行窗口（Windows 11 下默认由 Windows Terminal 托管）。关闭（默认）时完全不创建该窗口，scrcpy 的输出转进执行日志；打开时保留窗口原样显示，便于看它的原始日志。
- **最小化 / 恢复投屏窗口（全局快捷键）**：默认 `Ctrl+Alt+M`，同一个键切换——投屏窗口已最小化时按下就恢复并置于前台，否则把它最小化。只在投屏会话运行期间注册。
- **视频帧率上限**：对应 scrcpy 的 `--max-fps`，可选不限 / 120 / 90 / 60 / 45 / 30 / 24 帧。它决定每秒采集并编码多少帧，直接决定投屏带宽和手机的编码负载。手机上滑动卡顿时先试 60 或 30 帧。
- **视频码率**：对应 scrcpy 的 `--video-bit-rate`，可选 1 / 2 / 3 / 4 / 6 / 8 / 12 / 16 / 24 / 32 Mbps，默认 8 Mbps（与 scrcpy 自身默认一致）。网络不稳、画面出现马赛克或拖影时，调低比调高更有效；调高只在画面细节多（例如看视频）时才有意义。
- **分辨率上限**：对应 scrcpy 的 `--max-size`，可选不限制 / 1920 / 1600 / 1280 / 1080 / 720，限制的是长边像素，短边按比例缩放。手机竖屏 1200×2667 选 1600 时实际是 719×1600，像素数降到约 1/2.8。**想减轻手机编码负载和带宽压力，降分辨率比降帧率划算得多**——降帧率牺牲的是动画的流畅度，降分辨率牺牲的是静态清晰度，后者对操作手感影响小得多。
- **键盘输入方式**：对应 scrcpy 的 `--keyboard`，可选自动（scrcpy 默认，不传该参数）/ UHID（模拟物理键盘）/ SDK（系统接口注入）/ 关闭。实测这台小米上「自动」走的是 SDK——会话前后手机的输入设备列表完全一致，手机不认为接了外接键盘，输入框一聚焦就弹手机输入法；改成 UHID 后手机上会多出一个名为 `scrcpy` 的键盘设备（会话结束消失）。

投屏会话运行时，「投屏」按钮右侧会显示实时帧率（每秒刷新），丢帧时显示成 `24 fps（丢 2 帧）`。这个数据来自 scrcpy 的 `--print-fps`，靠捕获它的标准输出实现，所以**开启「显示 scrcpy 命令行窗口」时不可用**——那时输出被它自己的窗口接管了。

所有设置只有点对话框里的「保存」才会写盘；点「取消」或右上角关闭对话框都不会保存。程序退出时还会再落一次盘，避免内存里已生效的设置漏写。

scrcpy 3.3.3 已内置（Apache-2.0），不需要另外安装。默认带音频转发，手机的声音会从电脑放出来。

早期版本尝试过把投屏画面嵌进主界面（Win32 SetParent），实测画面闪一下就消失、投屏区只剩灰底，已按需求移除，只保留独立窗口；归档实现在 `BACKUP\DEL\WindowEmbedder.cs`。

## 手机文件面板

点工具条的「**手机文件**」展开右列面板，跟随当前选中的已连接设备；没连设备时面板禁用并提示。

界面分两列：左列自上而下是「全局工具条 → 设备表头 → 设备列表 → 分隔条 → 日志表头 → 执行日志 → 状态栏」，右列整列是手机文件面板（收起时列宽归 0，左列自动铺满）。

按钮**按位置分两组**：设备框上方那条工具条放**全局操作**（扫描局域网、无线调试配对、重启 adb、连接／断开连接）；日志框上方那一行放**连接后的操作**（打开 shell、复制地址、投屏／关闭投屏、手机文件、清空日志），并在最左侧显示「执行日志」标题。

「无线调试配对」是 **SplitButton**：直接点主体是一键配对；点右侧箭头展开菜单，里面是「手动添加设备（IP:端口）」。

两处分隔条都可以**拖动**调整占比：设备列表与执行日志之间的横向分隔条、以及左列与手机文件面板之间的纵向分隔条（只在面板展开时可拖）。两列/两行的尺寸都用星值表示，所以拖动后缩放窗口会按同一比例跟随；拖动时各自有最小尺寸限制（左列 360、面板 280、设备列表 160、日志 80 DIP）。

工具条和操作栏的按钮放在自定义的 `WrapPanel` 里，窗口变窄时自动折行，不会溢出被面板盖住。

窗口最小尺寸固定为 **900×620 DIP**，交给系统限制（`OverlappedPresenter.PreferredMinimumWidth/Height`，单位与 `AppWindow` 一致是物理像素，所以按窗口 DPI 折算）。

- 宽度 900：面板按默认比例占 1/3 时要保证左列 ≥ 360、面板 ≥ 280，反推 (280×3)+58 = 898，取 900。
- 高度 620：最窄左列下工具条与操作栏各折 2 行，加上设备列表 160 / 日志 80 与内外间距，实测约 518，留余量。
- 状态消息与「已选择：…」合并到窗口底部一条横跨整窗的状态栏里（详见「界面元素」）。以前「已选择」放在操作栏里，只能分到左列一半宽度，长设备名必定被截断成 `…`；放到整宽状态栏后实测 323 DIP 的全文能完整显示。

刻意**不用**按当前列比例动态反推最小尺寸：折行状态随宽度变化，动态下限会自我抬高（实测一路把窗口顶到 1305 DIP）。实测：面板展开时把窗口强行设成 300×300 物理，系统钳到 1350×930 物理 = 900×620 DIP，22 个按钮无一越界，设备列表 225 DIP、执行日志 79 DIP、面板内容 251 DIP 都在窗口内。

- **浏览**：面板打开时自动列 `/sdcard`。路径框可直接改，回车跳转；「上一级」回上层；「刷新」重列当前目录。双击目录进入，双击文件直接下载。
- **上传**：把文件或文件夹从资源管理器直接拖进面板，落到当前目录；也可以用「上传」按钮选文件。目录递归上传，同名覆盖。
- **下载**：右键条目选「下载到电脑」，落到设置里的下载目录（默认是 Windows 的「下载」文件夹，可在设置里改）。
- **右键菜单**：下载到电脑 / 重命名… / 删除 / 新建文件夹…。删除前会弹确认框，且不可恢复。

浏览范围不做限制，路径框里输入任何路径都行；无权限的目录会把 adb 的报错原样显示在面板底部，不会静默失败。

## 应用图标

蓝色圆角方块底 + 白色手机轮廓 + 右上角浅青色无线信号弧 + 屏内终端提示符 `>_`，对应这个程序的四件事：手机、无线、ADB、调试。改用 `assets\make_icon.py` 重新生成：

```powershell
cd CODEX\assets
python make_icon.py
```

- 图标是**代码绘制**的（Pillow，4 倍超采样后降采样），不是 AI 生成的位图：应用图标要在 16px 下保持锐利，几何图形直接画质量更可控。
- 16 / 24 px 单独出一版**简化稿**（去掉提示符与听筒、线条加粗），32 px 及以上用细稿，因此 `app.ico` 里各尺寸不是同一张图缩放来的，容器是手写的（Pillow 的 ICO 保存不支持逐尺寸指定不同画面）。
- 产物：`ADBDevTool\Assets\app.ico`（256/128/64/48/32/24/16 七帧，构建时由 csproj 的 `ApplicationIcon` 嵌进 exe）；`assets\app-icon.png`、`app-icon-small.png` 是预览图。
- 非打包的 WinUI 窗口自身不带图标（实测窗口大小图标句柄都是 0），所以启动时用 `ExtractIconEx` + `WM_SETICON` 把 exe 里的图标显式设到窗口上，不依赖系统的回落规则。

## 实现要点

- 设备发现走 adb 内置的 mDNS 后端（`adb mdns services`），同时列出 `_adb-tls-connect._tcp`（连接端口）与 `_adb-tls-pairing._tcp`（配对端口）。Android 11+ 的无线调试端口是随机的，只能靠 mDNS 发现，扫端口扫不出来。
- 配对与连接是两个不同端口：先 `adb pair <配对端口> <配对码>`，成功后再 `adb connect <连接端口>`，程序会自动从 mDNS 列表里找同一 IP 的连接端口。
- 连接失败且错误里没有 "connected to" 时，界面会提示「多半是还没配对」，因为端口能通但 TLS 握手需要配对密钥（`%USERPROFILE%\.android` 下的 adbkey）。
- 程序给 adb 进程注入 `ADB_MDNS_AUTO_CONNECT=0`，关掉 adb 自带的 mDNS 自动连接（实测：以该值启动的 daemon 在 18 秒内不会自动连上已配对设备）。否则手机上刚开无线调试就被 adb 偷偷连上，「连接 / 断开连接」两个按钮会失去意义。若 adb 服务已被 Android Studio 等其它工具启动，需要点一次「重启 adb」才应用该设置。
- 同一台手机在 `adb devices -l` 里可能出现两条记录：`10.42.0.131:36549` 与 `adb-XXXX._adb-tls-connect._tcp`。程序按 mDNS 服务名把它们归并成一条，优先保留 `IP:端口` 形态。
- 设备列表内容变化时整体重建，ListView 会在下一个布局周期再处理一次选中状态，把刚设好的选中项清掉。重建后恢复选中要连补两次（立即一次 + 队列空一拍再一次），否则断开连接后选中丢失，连接按钮会直接变灰。
- 「断开连接」会依次断开该设备的两种 serial 形态，否则只断开其中一条时设备仍显示在线。
- 投屏复用程序自带的 adb：通过环境变量 `ADB` 把 scrcpy 指向 `platform-tools\adb.exe`，实测进程列表里不会出现 scrcpy 目录自带的那份 adb，因此分发时可以不带它。
- 隐藏 scrcpy 的控制台窗口靠 `CreateNoWindow = true`，但它必须和标准输出重定向同时用：单独设 `CreateNoWindow` 时实测 scrcpy 立刻以退出码 1 退出（拿不到有效的标准输出句柄），加上重定向之后实测控制台窗口数为 0、SDL 投屏窗口正常、日志能从管道读出。重定向的流必须显式按 UTF-8 解码，否则中文路径会变乱码。
- 排查投屏卡顿时先用数据说话：scrcpy 的 `-b/--video-bit-rate` 默认 **8 Mbps**、`-m/--max-size` 默认 **0（不限制，按手机原生分辨率编码）**。本机实测 Wi-Fi 是 5 GHz / 802.11ac、协商速率 400 Mbps、信号 94%，即链路余量约 50 倍，所以纯带宽一般不是瓶颈，更值得怀疑的是 Wi-Fi 时延抖动、原生 1200x2670@120Hz 的编码负载，以及默认开启的音频转发。
- 不要用 `ProcessStartInfo.WindowStyle = Minimized` 代替隐藏：STARTUPINFO 的显示状态会被进程创建的**第一个**窗口继承，实测 scrcpy 的 SDL 投屏窗口会跟着一起最小化。早期版本的「启动后单独最小化控制台」实现已退役，归档在 `BACKUP\DEL\ScrcpyConsoleMinimize.removed.cs`。
- 设置存放于 `%LOCALAPPDATA%\ADBDevTool\settings.json`（用 `System.Text.Json`），不放程序目录，免得绿色文件夹被放到只读位置时写不进去；文件缺失或损坏时回落到默认值。
- 实时帧率用 scrcpy 的 `--print-fps`，它每秒往标准输出打一行 `INFO: NN fps`（丢帧时附加 `(+N frames skipped)`）。程序把匹配这行的输出分流到帧率标签，其余照旧写进执行日志，避免每秒一行把日志刷满。
- 设置对话框内容是 ScrollViewer，高度取 `XamlRoot.Size.Height - 260`（下限 220）。对话框自身高度由内容决定，不设上限的话内容一长就会把按钮顶出窗口。
- 窗口尺寸一律按 DIP 计算再折算物理像素：`AppWindow.Resize`／`AppWindow.Size` 的单位都是**物理像素**，直接按 DIP 写会在 150% 缩放的机器上得到一半大小的窗口（实测本机 DPI 144，写 1320 只得到 880 DIP 宽）。默认尺寸 1320×860 DIP。展开手机文件面板时，若左列拿不到 660 DIP，就把窗口撑到 660+420+42=1122 DIP（上限为主屏工作区宽度），面板宽度在 320~420 之间随剩余空间收缩。这里的 660 DIP 是操作栏的硬需求：四个按钮加实时帧率约 524 DIP，再加选中设备文字——左列不够宽时操作栏会溢出自己的单元格，被右列的面板盖住（投屏按钮被部分遮挡就是这么来的，Grid 子元素默认不裁剪）。
- 设置对话框把 scrcpy 相关项收进两个可折叠分组（Expander，默认收起）：「投屏画面」放帧率/码率/分辨率，「投屏窗口与输入」放关屏/命令行/快捷键/键盘模式。分组标题带一行当前值摘要，收起状态下也能看到配置；摘要在控件变化时刷新。非 scrcpy 的设置（下载目录）留在顶层。
- 列目录的远端路径**必须带尾斜杠**：设备上 `/sdcard` 是指向 `/storage/self/primary` 的符号链接，不带斜杠时 toybox ls 只列链接自身（实测只回一行），带斜杠才列内容。`AdbService.ListRemoteDirectoryAsync` 里统一补斜杠。
- 路径引号分两套，混用会直接失败：`adb shell <cmd>` 里的路径走设备 shell，用 POSIX 单引号（`ShellQuote`，内部单引号写成 `'\''`）；`adb push/pull` 的两端路径不经过设备 shell，用双引号（`WindowsQuote`）。实测给 pull 的远端路径加单引号时 adb 会收到带字面引号的路径，报 `failed to stat remote object`。
- 传输进度：`adb push/pull` 重定向后只有一行汇总（实测 30 MB 文件），没有百分比。因此下载改为轮询落地文件大小换算百分比（`TrackDownloadProgressAsync`，300 ms 一拍，结果经 DispatcherQueue 回 UI），上传用不确定态进度条加状态文字。
- 自带一个 `WrapPanel`（`Controls/WrapPanel.cs`）给工具条和操作栏做自动折行，不引入第三方依赖。关键不变量：**MeasureOverride 返回的期望宽度必须收敛到可用宽度**，否则父级 Grid 会被「不折行所需宽度」撑宽、可用宽度随之变大，折行判据永远不成立——实测表现为按钮排成一行并被窗口边缘裁掉。ArrangeOverride 里也要按「剩余宽度」而不是「整格宽度」给子元素定宽，否则折行后最后一个元素会被压成很窄的一条。
- 分隔条是自定义的 `SplitterThumb`（`Controls/SplitterThumb.cs`）：WinUI 的 `Border` 是 sealed 不能继承，`UIElement.ProtectedCursor` 又是 protected，所以以 `ContentControl` 为基类再派生一个类型来设置拖动指针形状。
- 投屏窗口的最小化/恢复用**一个**全局热键切换，按当前 `IsIconic` 状态决定动作。之所以走全局热键（RegisterHotKey），是因为焦点在 scrcpy 窗口上时本程序收不到按键。热键挂在自建的 message-only 窗口上，不去子类化 WinUI 主窗口的过程函数，避免干扰 XAML 的消息处理；只在投屏会话期间注册。
- 抢前台受 Windows 前台锁限制，按此顺序回退：SetForegroundWindow → AttachThreadInput 挂到前台线程后再调用 → SwitchToThisWindow（未公开接口，作为兜底，失效条件是 user32 不再导出它）。实测裸调用会被挡掉，AttachThreadInput 对经典 Win32 前台程序有效，对 UWP 一类前台窗口仍可能失败。
- 保存设置后必须把焦点还给投屏窗口：点击「设置」按钮本身就使前台切到本程序，对话框再抢一次，保存后焦点留在我们这边，用户接着往手机打字会全部落空。这里不能用「打开对话框前记住投屏窗口是否是前台」来判断——点击事件到达处理器时前台已经是本程序，条件恒为假。实测：改帧率并保存后前台从投屏窗口变成本程序；归还逻辑加上后前台回到投屏窗口。
- 「投屏时关闭手机屏幕」走 scrcpy 的 `-S`。实测 scrcpy 服务端会打印 `[server] INFO: Device display turned off`，但在小米 24129PN74C / Android 16 上，同一时刻 `dumpsys display` 的物理屏 `state`/`committedState` 与 `dumpsys window policy` 的 `mScreenOn` 仍报 ON，两边说法不一致——**以手机屏幕实际是否熄灭为准**，不生效时可退回 `adb shell input keyevent 223` 主动关屏。
- scrcpy 的进程退出事件经消息队列转发后才执行，期间可能已经开了新会话，回调里要核对事件来源进程，否则旧会话退出会清掉新会话状态（表现为「关闭投屏」变灰、进程变孤儿）。
- `EnableMsixTooling` 必须为 `true`：非打包应用也要靠它生成 `resources.pri` 与 XBF 资源，否则启动时报 `ms-appx:///MainWindow.xaml` 找不到。

## 排查

- **列表一直是空的**：确认手机和电脑在同一网段、手机「无线调试」处于打开状态、路由器没开 AP 隔离；程序重启 adb 后再扫一次。
- **列表里的设备突然消失**：Android 在息屏、切网、关闭无线调试后会停止 mDNS 广播，此时点「手动添加」，填手机无线调试页面上的 `IP:端口` 直接连接即可。
- **连接失败**：先做一次配对；或者手机无线调试关掉再打开（端口会变，重新扫描即可）。
- **状态是「待授权」**：看手机屏幕，点「允许 USB 调试」。
- **投屏按钮是灰的**：它只对状态为「已连接」的设备生效，先连接并选中再点。
- **面板列不出目录**：看面板底部的报错——目录无权限时 adb 会把原因写在那一行。另外路径若指向符号链接，程序已自动补尾斜杠；手写路径时不要带 `~` 之类设备 shell 才认的写法。
- **上传/下载失败**：日志里能看到完整的 adb 命令。远端或本地路径含空格时程序会自动加引号，若仍失败，先确认路径确实存在于手机端（面板里看到的路径为准）。
- **往手机打字没反应**：投屏窗口必须在前台才能接收键盘输入，焦点在别的窗口时字母不会进手机。改动设置点「保存」后，程序会自动把焦点还给投屏窗口；如果手动切到了别的程序，点一下投屏窗口即可。
- **数字和控制键能进手机、字母进不去**：手机输入法处于中文状态，把注入的字母当拼音吃掉了（数字在输入法里是选词路径，控制键直接交给应用，所以看起来正常）。把手机输入法切到英文即可。相关实测：`show_ime_with_hard_keyboard` 设成 0 无效——系统确实跟随该设置（改 1 服务报 2、改回 0 报 1），但即使强制 `--keyboard=uhid` 让手机认出键盘设备后，`mInputShown` 仍为 true，这台 MIUI 不接受「有外接键盘就不显示软键盘」。
- **投屏没画面**：看界面执行日志里 `scrcpy -s ...` 那一行之后有没有报错；scrcpy 会把自己的服务端推到手机并在手机上起进程，若手机弹授权提示需要允许。
- **程序启动无窗口**：看 `dist\ADBDevTool\crash.log`。
